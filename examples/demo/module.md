# demo

## 模块

### sensing · 传感
概要：生成目标值和带扰动的测量值。
详细：读取信号参数，以每秒 50 次的节奏生成目标值和带噪声的测量值。将两项数值发送给控制端，不接收执行端的位置反馈。

### sensing/signal · 目标生成
概要：生成按规律起伏的目标值。
详细：输入启动后的经过时间，以及配置中的幅度和频率，生成正弦变化的目标值。每秒输出 50 个目标值，供测量生成使用。

### sensing/measurement · 测量生成
概要：给目标值加入随机扰动并发送。
详细：输入目标值、噪声大小和发送端口，在目标值上叠加均值为零的高斯噪声，得到测量值。每秒将目标值和测量值一起编码为 JSON，通过本机 UDP 发送给控制端。

### control · 控制
概要：根据测量值和位置决定如何运动。
详细：集中描述运行配置，并接收传感数据和执行端的位置反馈。每秒计算 50 次控制量，发送给执行端，同时保存每个周期的运行记录。

### control/config · 配置文件
概要：保存运行前需要读取的参数。
详细：保存信号幅度、信号频率、噪声大小、平滑窗口大小、控制系数和通信端口。三个进程各自在启动时读取同一份 JSON 配置，取得各自需要的参数；运行期间没有重新加载配置的逻辑。

### control/regulation · 平滑与调节
概要：平滑测量值并计算运动指令。
详细：以 50 Hz 读取最新传感数据和位置，将收到的测量值放入有限长度的窗口并求平均，没有新数据时沿用已有数据。用平滑值减去位置得到偏差，结合累计偏差和偏差变化计算控制量，再发送给执行端；目标值只用于记录，不直接参与偏差计算。每周期输出经过时间、目标值、平滑值、位置和控制量，交给日志子模块保存。

### control/logs · 日志文件
概要：逐次保存控制过程中的数值。
详细：启动时创建带时间标记的 CSV 日志并写入表头，接收控制端每周期生成的五项记录。按时间、目标值、平滑值、位置和控制量的顺序追加到磁盘，时间保留四位小数。代码没有读取日志或回放日志的逻辑。

### execution · 执行
概要：模拟运动并管理程序启停。
详细：接收控制量，每秒更新 100 次模拟速度和位置，并将位置反馈给控制端。还提供统一启动三个进程及退出时清理进程的入口，实际执行对象是数值模拟而非硬件。

### execution/communication · 指令与反馈
概要：接收运动指令并回传当前位置。
详细：启动时读取指令接收端口和位置发送端口，在本机通过 UDP 交换 JSON 数据。以 100 Hz 取出最新控制量并转为数值，没有新指令时沿用上次控制量，初值为零。将控制量交给运动模拟，并把运动模拟返回的位置发送给控制端。

### execution/motor · 运动模拟
概要：按指令更新速度和位置。
详细：输入控制量，以 0.01 秒步长和 0.2 秒时间常数，使速度逐步接近控制量，再用更新后的速度推进位置。位置和速度初始均为零，每秒输出 100 次更新后的位置，供通信子模块回传。

### execution/process · 进程启停
概要：统一启动和结束三个程序。
详细：输入启动操作，通过运行工具在后台依次启动执行、控制和传感三个进程，并保存进程编号。收到中断、终止信号或启动脚本退出时，向这些进程发送终止请求并等待结束。

## 数据流
- control/config -> sensing/signal : signal_parameters | 目标参数 | 数值 | 配置 | JSON 数值包含幅度 1.0 和频率 0.2，幅度未注明物理单位，频率单位为 Hz；传感进程启动时读取一次。
- control/config -> sensing/measurement : measurement_parameters | 测量参数 | 数值 | 配置 | JSON 数值包含噪声标准差 0.1 和发送端口 9001，噪声未注明物理单位，端口为无单位整数；传感进程启动时读取一次。
- control/config -> control/regulation : regulation_parameters | 调节参数 | 数值 | 配置 | JSON 数值包含窗口大小 10、比例系数 2.0、积分系数 0.5、微分系数 0.1，以及传感接收端口 9001、位置接收端口 9002、指令发送端口 9003。窗口大小单位为样本数，控制系数未注明单位，端口为无单位整数；控制进程启动时读取一次。
- control/config -> execution/communication : execution_ports | 执行端口 | 数值 | 配置 | JSON 整数包含指令接收端口 9003 和位置发送端口 9002，均无单位；执行进程启动时读取一次。
- sensing/signal -> sensing/measurement : target_value | 目标值 | 曲线 | 实时 | 浮点数，代码未注明物理单位；按 50 Hz 生成，作为叠加噪声前的基础数值。
- sensing/measurement -> control/regulation : sensor_sample | 传感数据 | 曲线 | 实时 | UDP 承载的 JSON 对象包含目标值和测量值两个浮点数，均未注明物理单位。发送频率为 50 Hz，控制端以 50 Hz 读取并仅保留接收缓冲区内最新一包。
- control/regulation -> execution/communication : control_command | 控制指令 | 曲线 | 实时 | UDP 承载的 JSON 对象包含一个控制量浮点数，代码未注明物理单位。发送频率为 50 Hz，执行端以 100 Hz 读取最新指令，无新指令时保持原值。
- execution/communication -> execution/motor : applied_command | 当前指令 | 曲线 | 实时 | 浮点数控制量，代码未注明物理单位，在运动模型中作为速度趋近的目标；每个 100 Hz 更新周期使用一次。
- execution/motor -> execution/communication : simulated_position | 模拟位置 | 曲线 | 实时 | 浮点数位置，代码未注明物理单位；以 100 Hz 输出每次运动更新后的结果。
- execution/communication -> control/regulation : position_feedback | 位置反馈 | 曲线 | 实时 | UDP 承载的 JSON 对象包含一个位置浮点数，代码未注明物理单位。发送频率为 100 Hz，控制端以 50 Hz 读取最新位置，无新数据时沿用原值。
- control/regulation -> control/logs : cycle_log_record | 周期记录 | 文本 | 实时 | 五个浮点数组成的列表，包含经过时间、目标值、平滑值、位置和控制量，每秒约 50 条；时间单位为秒，其余数值未注明物理单位。日志子模块将其写成 CSV 文本行，代码没有写入后的读取数据流。
